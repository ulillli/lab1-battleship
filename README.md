# Морской бой на Java RMI

## Запуск

Сборка (из папки `battleship-rmi`):

```
.\mvnw.cmd compile
```

Три терминала: сервер и два игрока.

```
java -cp target\classes battleship.GameImpl
java -cp target\classes battleship.Client
java -cp target\classes battleship.Client
```

Для игры по сети серверу передаётся его собственный IP, клиентам - IP сервера:

```
java -cp target\classes battleship.GameImpl 192.168.1.5
java -cp target\classes battleship.Client 192.168.1.5
```

## Правила

Поле 10x10, корабли: 1 четырёхпалубный, 2 трёхпалубных, 3 двухпалубных, 4 однопалубных,
без касания друг друга (в том числе по диагонали), расстановка случайная.
Клетка для выстрела: буква A-J и число 1-10, например `E5`.
Попал - стреляешь снова, промахнулся - ход соперника.
Игра заканчивается, когда у одного из игроков потоплены все корабли.

## Как устроено

По схеме из презентации: интерфейс - реализация на сервере - реестр - клиент.

| Класс | Что делает |
|---|---|
| `Game` | удалённый интерфейс, наследует `java.rmi.Remote`, методы бросают `RemoteException` |
| `GameImpl` | реализация, наследует `UnicastRemoteObject`; в `main` создаёт реестр `LocateRegistry.createRegistry(1099)` и регистрирует объект под именем `Battleship` |
| `Client` | `LocateRegistry.getRegistry(host, 1099)`, `lookup("Battleship")`, дальше вызывает методы как обычные |
| `Field` | поле игрока (только на сервере): номера кораблей в клетках, сделанные выстрелы, оставшиеся палубы |

Методы `Game`:

| Метод | Что возвращает |
|---|---|
| `join()` | номер игрока 0 или 1 (-1, если мест нет) |
| `getTurn()` | чей ход (-1, пока не подключились оба) |
| `getWinner()` | номер победителя или -1 |
| `getBoards(player)` | своё поле с кораблями и поле соперника без них, текстом |
| `shoot(player, row, col)` | «мимо», «ранил», «убил» или «сюда уже стреляли» |

Параметры и результаты - примитивные типы и строки, они передаются по значению.
Клиент раз в 0,5 с спрашивает `getTurn()`; когда наступает его ход, показывает поля и делает выстрел.
Методы `GameImpl` объявлены `synchronized`: RMI выполняет вызовы разных клиентов в разных потоках,
и без блокировки возможны «гонки потоков», о которых говорится в презентации.
